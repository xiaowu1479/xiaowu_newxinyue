## 2. 固定约定（重要）

1. **不要再发布 GitHub Release**。后台更新只读仓库里的 `manifest.json` 和文件原文，Release 不参与任何流程。
2. 如果哪次确实要建 Release，**标题只用纯数字**（如 `2.0.4`），不要写中文描述。
3. **不要打包压缩包**。服务器部署直接从仓库拉取或在服务器上 `git clone`。
4. 只维护 `main` 一个分支，不要留 `php8-compat`、`snapshot-*` 之类的分支。
5. 凭证类文件永远不进仓库：
   - `config/*_auth.json`
   - `config/*_device.json`
   - `extend/netdisk/pan/*token*.json`
   - `.env`

## 3. 发布步骤

### 3.1 改版本号与更新日志

```powershell
# VERSION 必须是 UTF-8 无 BOM、单行
[IO.File]::WriteAllText("$PWD\VERSION", "2.0.4`n", (New-Object System.Text.UTF8Encoding($false)))
```

编辑 `CHANGELOG`，在最上方 `## 日期` 段落下追加条目（格式：`- 新增/修复/适配：说明`）。

### 3.2 重算文件清单

```powershell
$php = "d:/local_php_build/phpstudy_pro/Extensions/php/php8.2.9nts/php.exe"
& $php tools/make_manifest.php
```

输出应包含：

```
文件数   : 965
版本号   : 2.0.4
SQL 版本 : 20261001
```

> `manifest.json` 是后台更新的依据，**改了任何 `app/`、`config/`、`extend/`、`route/`、`public/static/`、`public/views/` 下的文件都必须重算**。
> 根目录文件（`docs/`、`README.md`）不影响清单，不需要重算。

### 3.3 提交并推送

本地没有配置 `user.name` / `user.email`，提交时必须用命令参数指定：

```powershell
git add -A
git -c user.name="xiaowu1479" `
    -c user.email="168272602+xiaowu1479@users.noreply.github.com" `
    commit -m "fix: 说明本次改动"

git tag -a v2.0.4 -m "2.0.4"
git push origin main --tags
```

> `git push` 的输出会以红色 stderr 形式显示在 PowerShell 里，**只要看到 `main -> main` 和 `[new tag]` 就是成功**，不用管报错外观。

### 3.4 验证

```powershell
# 远程 main 是否是新提交
git ls-remote origin refs/heads/main

# 远程清单是否已更新（GitHub CDN 有约 5 分钟缓存）
Invoke-RestMethod -Uri "https://raw.githubusercontent.com/xiaowu1479/xiaowu_newxinyue/main/manifest.json?t=$(Get-Random)" -Headers @{ 'Cache-Control'='no-cache' } |
    Select-Object version, sql_version
```

## 4. 服务器侧更新方式

后台「系统更新」的配置必须是：

| 配置项 | 值 |
|---|---|
| 更新源类型 | `github` |
| GitHub 仓库 | `xiaowu1479/xiaowu_newxinyue` |
| 分支 | `main` |

对应数据库：

```sql
SELECT conf_key, conf_value FROM qf_conf WHERE conf_key LIKE 'upgrade_%';
```

如果 `upgrade_source` 是 `server`，检测更新会去请求旧主服务器，显示它的版本号（`1.0.0`），看起来像 bug，实际是源选错了。

---

## 5. 已知坑位

| 现象 | 原因 | 处理 |
|---|---|---|
| 检测更新显示「最新版本 v1.0.0」 | `upgrade_source = server`，请求到了旧官方源 | 改成 `github` |
| 推送后立刻检测还是旧版本 | GitHub raw CDN 约 5 分钟缓存 | 等几分钟再点 |
| 安装页出现 `Warning: Undefined array key "install"` | PHP 8 未定义键（2.0.3 已修） | 升级到 2.0.3+ |
| 服务器切 PHP 版本提示 `require 7.2.0 < PHP <= 7.3.0` | 服务器根目录存在旧的 `composer.json`（不在本项目内） | 改约束或重命名该文件 |
| 重装后管理员登录不上 | `.env` 的 `SYSTEM_SALT` 与旧站不一致 | 保持与旧站相同的值（本项目为 `心悦`） |
| 后台更新把本地改动覆盖 | 更新是镜像覆盖，会删除远端没有的文件 | 所有改动先提交到仓库 |

## 6. 目录与环境

```ini
# .env（不在仓库里，需要手动创建）
APP_DEBUG = false
SYSTEM_SALT = 心悦

[DATABASE]
TYPE = mysql
HOSTNAME = 127.0.0.1
DATABASE = xinyue
USERNAME = xinyue
PASSWORD = ******
HOSTPORT = 3306
CHARSET = utf8mb4
PREFIX = qf_
```

- 站点根目录必须指向 `public/`
- `runtime/`、`public/uploads/` 需要可写
- 安装完成后删除 `public/install/`
- PHP 8.0 ~ 8.2 可用（推荐 8.2），已通过 `Php8Compat` 中间件处理弃用告警
